# Apply learning

Create the smallest useful attempt that takes knowledge outside passive review. Use the active vault's objects and vocabulary rather than importing a personal or academic taxonomy.

## Ground the application

Confirm the active vault boundary. Read its agent guide, BP Vault contracts, the source note, and relevant learning evidence. If the contracts are missing, recommend `setup-bp-vault` before writing. Use the note's language and keep every link inside the active vault.

Clarify the capability the user wants to exercise. If the available evidence reveals a prerequisite gap, recommend `test-understanding` as the immediate route instead of disguising another study note as an application.

## Propose one attempt

Default to one application small enough to attempt before it turns into a planning project. Adapt its form through the method contract. A personal vault might map it to an experiment, action, or project. An academic vault might map it to an exercise, unaided explanation, or practice. Those are examples, not required categories.

The proposal must identify:

- the context in which the attempt will happen;
- the action, behavior, exercise, or artifact;
- an observable success criterion;
- the evidence to retain;
- a concrete moment or condition for review.

Show the proposal and the exact destination before creating or substantially editing a note. Wait for approval. Then write using the local template, properties, and links. If the vault has no application object or property mapping, use ordinary prose in an approved existing location rather than inventing schema.

Do not schedule a review or automation. Record the agreed review moment only. Finish with the application, success criterion, and where its evidence will be found.
