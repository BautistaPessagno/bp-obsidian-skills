# Develop note

Develop a capture according to its intent while preserving the vault's meaning and structure. A developed note is documented well. It is not necessarily learned.

## Grounding

Find the active vault boundary. Read its agent guide plus the BP Vault structure and method contracts. If either contract is missing, stop before editing and recommend `setup-bp-vault`.

Read the whole note, its properties, local category context, directly relevant links, and the sources needed to interpret it. Follow the local source hierarchy. Keep facts, interpretations, and experience distinct, and show material conflicts instead of silently choosing a winner. Use the installed `obsidian-markdown` skill for syntax.

## Choose the intent

Infer intent from the content, local object type, source, and request. State the inference briefly. Ask one focused question when two intents would lead to meaningfully different edits.

Load only the matching mode:

- [Thought](./references/thought.md) for an idea, reflection, observation, or open question.
- [Decision](./references/decision.md) for a choice whose reasons and consequences matter.
- [Reference](./references/reference.md) for source-grounded material whose provenance and scope matter.
- [Learning](./references/learning.md) for material the user intends to retrieve, transfer, or apply.

## Propose, approve, edit

Build a draft in the note's language. Preserve its useful voice and uncertainty. Include only semantic links that resolve inside the active vault and follow its link conventions.

Apply mechanical maintenance directly only when the structure contract authorizes it. Before a semantic rewrite, new note, split, move, rename, or changed meaning, show the draft and structural actions, then wait for explicit approval. Invocation authorizes the ordinary analysis and proposal, not those substantial changes.

After approval, make only the approved edits. Map the conceptual state "developed" to a property only when the local method contract defines that mapping. Never invent a status property. The "learned" state remains unchanged unless an observed `test-understanding` session has met the local evidence rule.

Finish by naming what changed, unresolved conflicts or questions, and any justified next step. Suggest `test-understanding` only when learning is the user's intent.
